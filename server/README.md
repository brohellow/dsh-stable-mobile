# 手机访问多租户方案（你的服务器 + 多个朋友）

用你的服务器当总入口，每个朋友用**自己的密码**登录**自己电脑上的 DSH**。

```
朋友 A 手机 → https://你的域名:18100/ → nginx → 隧道 19100 → A 的电脑 DSH
朋友 B 手机 → https://你的域名:18101/ → nginx → 隧道 19101 → B 的电脑 DSH
你自己    → https://你的域名:7000/  → （原主站，不受影响）
```

---

## 核心安全设计

**绝对不要给朋友发你的服务器私钥。** 那样等于把服务器整个交出去。

正确做法（本方案已实现）：

| 隔离层 | 机制 | 效果 |
|---|---|---|
| 账户 | 每人一个 `dshu-<名字>` Linux 账户 | 互相看不到对方文件 |
| 认证 | 每人独立 ed25519 密钥，只装在自己账户 | 密钥泄露只影响一个人 |
| 端口 | `PermitListen 127.0.0.1:<自己的端口>` | **开不了别人的端口，也开不了 22/80** |
| 转发 | `PermitOpen none` | 不能做本地转发（不能拿服务器当跳板） |
| 登录 | `nologin` shell + `PermitTTY no` | 不能拿 shell，只能建隧道 |

已实测验证（见下方"验证记录"）：朋友用自己密钥尝试绑 18105、18081、22 **全部被拒**，只有自己的端口成功。

## 部署步骤

### 一次性初始化（你自己做）

```bash
# 把 tenant-server/ 下三个脚本传到服务器
scp -i 你的密钥 dsh-tenant*.sh ubuntu@你的服务器:/tmp/

ssh -i 你的密钥 ubuntu@你的服务器
sudo bash /tmp/dsh-tenant-setup.sh 你的域名
```

**然后在云控制台放行端口**：安全组 / 防火墙 → 放行 TCP `18100-18199`。

> ⚠️ 这一步必须手动做，脚本改不了云平台安全组。

### 每加一个朋友

```bash
sudo dsh-tenant add alice      # 输出私钥 + 分配端口
sudo dsh-tenant-nginx 你的域名  # 刷新 nginx
```

把 `add` 输出的**私钥内容**和访问地址发给对方。

### 日常管理

```bash
sudo dsh-tenant list              # 看所有租户、端口、在线状态
sudo dsh-tenant reset-key alice   # 密钥泄露时轮换
sudo dsh-tenant remove alice      # 删人，端口自动回收
```

## 端口规划

| 用途 | 范围 | 谁监听 | 要放行吗 |
|---|---|---|---|
| 公网 HTTPS | 18100–18199 | nginx | ✅ 安全组要放行 |
| 隧道（回环） | 19100–19199 | sshd | ❌ 不需要 |

公网端口 = 隧道端口 - 1000。**不要让 nginx 和 sshd 抢同一个端口**，否则隧道会报 `remote port forwarding failed`（这是踩过的坑）。

## 朋友那边怎么配

朋友装插件 `dsh-stable-mobile`（[发布包](../发布/dsh-stable-mobile-1.0.0.zip)），在「设置 → 手机访问 → 高级设置」填：

| 字段 | 填什么 |
|---|---|
| 服务器地址 | 你的域名或 IP |
| SSH 用户 | 你给他分配的 `dshu-<名字>` |
| **私钥路径** | 你发给他的私钥文件路径（**不是你自己的密钥**） |
| 远端端口 | 你分配给他的**隧道端口**（19xxx，不是公网端口） |
| 公网地址 | `https://你的域名:<他的公网端口>` |

> ⚠️ 关键点：插件的「远端端口」要填 **19xxx 隧道端口**，不是 18xxx 公网端口。
> 因为 nginx 已经占了 18xxx，隧道必须绑 19xxx，由 nginx 转过去。

## 踩过的坑（都已修复）

1. **锁账户导致密钥登录失败**
   `useradd` 默认把密码字段设成 `!`（锁定），sshd 会**拒绝锁定账户的密钥登录**，
   日志表现为 `Connection reset ... [preauth]`。
   修复：`usermod -p ''`（空密码 + 系统 `PermitEmptyPasswords no` = 只能用密钥）。

2. **`AgentForwarding` 不是合法指令**
   正确写法是 `AllowAgentForwarding`，写错会让 `sshd -t` 直接失败。
   脚本已内置校验并自动回滚。

3. **`ForceCommand /bin/false` 会掐断反向转发**
   如果想让用户不能执行命令，用 `PermitTTY no` + `nologin` shell 即可，
   加 `ForceCommand` 反而会让 `-N` 隧道建不起来。

4. **nginx 和 sshd 抢同一端口**
   两者都绑同一个端口时，先绑的赢，另一个永远失败。必须端口分离（见上方规划）。

5. **Windows 上私钥文件权限**
   下载下来的私钥权限过宽，ssh 会拒绝加载（`UNPROTECTED PRIVATE KEY FILE`）：
   ```powershell
   icacls 私钥路径 /inheritance:r /grant:r "$($env:USERNAME):(R)"
   ```

## 和"每人各自部署"的对比

| | 共用你的服务器 | 每人自己搭 |
|---|---|---|
| 朋友门槛 | 装插件 + 填配置 | 要有服务器 + 配 nginx + 证书 |
| 你的责任 | 维护服务器、管端口、管密钥 | 无 |
| 安全风险 | 集中在你（已做隔离） | 分散 |
| 端口消耗 | 每人 1 个公网端口 | 无 |

如果朋友不多（<20 人），共用方案更省事；人多建议让他们自己搭，你只提供插件。
